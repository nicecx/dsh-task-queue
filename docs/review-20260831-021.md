## 020 审核三意见及修正

### 意见1: log() 时间戳破坏 monitor 稳定性契约
**问题**: `log()` 打印 `{now_iso()}` 时间戳；`--monitor-script` 要求 output 稳定（no timestamps）。同一异常因时间戳变化每 tick 重触发 agent（噪声，最多 MAX_ATTEMPTS 次）。
**修复**: `log()` 去掉时间戳，改固定前缀 `[task-queue-consumer]` + 任务 id + 稳定 note。
```python
def log(msg):
    print(f"[task-queue-consumer] {msg}", flush=True)
```
docstring 输出约定同步注明「无时间戳」。

### 意见2: reset 门禁拒绝误烧 attempts
**问题**: `guardian_cooldown_ok()`（10min 退避）/ `single_instance_ok()`（多实例）拒绝时 `execute_task` 返回 False → `main()` attempts+1；冷却期内每分钟重试约 4 次后置 failed——冷却期内的 reset 任务被永久丢弃而非等待冷却结束。
**修复**: `execute_task` 改三态返回 `(result, note)`，`result ∈ {done, defer, failed}`：
- `defer`（门禁拒绝）: 不累加 attempts、status 保持 `queued`，下次 cron 再试（冷却过了自然执行）；
- `failed`（真实执行失败: kickstart 失败等）: 才计 attempts；
- `done`: 完成（含 review 去重——使命已达成，标记 done 清理队列）。

### 意见3: off-by-one
**问题**: `task['status'] = 'failed' if task['attempts'] > MAX_ATTEMPTS` 使任务实际尝试 4 次（attempts 到 4）才 failed，与 MAX_ATTEMPTS=3 语义不符。
**修复**: 改 `>= MAX_ATTEMPTS`（attempts 到 3 即 failed）。
