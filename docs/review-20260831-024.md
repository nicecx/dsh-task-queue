## 023 四意见逐条落实

### 意见1 [approve tier]：消费者无 approve handler，cron 抢单会烧 attempts
**落实**: cron 消费者 `pickNext` **过滤 approve tier**（永不认领 approve 任务）：
```python
# pickNext 候选过滤追加：
if t.get("tier") == "approve":
    continue  # approve 仅由快道同步直调认领，cron 消费者不碰
```
approve 任务生命周期：入队（status=queued）→ 快道同步直调（busy_mutex 获取后立即认领 status=processing → 执行裁决 → done/failed）。cron 过滤后 approve 任务不会被抢单烧 attempts；若快道异常未认领，approve 任务保持 queued 不执行（裁决走原 Hermes 直调兜底）。

### 意见2 [reset tier]：内联重启丢失 08-31 预隔离修复，语义降级
**落实**: reset tier 执行 = **调用 reset_agent.py v2 全流程**（预检 → 重启前预隔离 dsh-tools 分裂 → SIGTERM+KeepAlive 三段式 → 健康检查 ≤3 轮 → recovery），不内联重启。消费者 reset handler 改为：
```python
if tier == "reset":
    # 门禁（冷却/多实例）→ defer
    # 执行：触发 reset_agent.py（复用 v2 预隔离+健康检查+恢复全流程）
    r = subprocess.run(["python3", RESET_AGENT, "--once"], ...)
    # 成功 → done；失败 → failed（计 attempts）
```
现有消费者内联三段式重启代码删除（避免双路径漂移）；`RESET_AGENT = ~/.dsh/reset-handoff/.../reset_agent.py`（部署时注入路径）。门禁（10min 退避/多实例）保留在消费者侧（defer 不烧 attempts）。

### 意见4 [payload 契约]：4 入队侧无统一 schema
**落实**: 统一 payload 契约表（与消费者代码一一对应）：

| tier | payload 键（必填） | 消费者读取 |
|---|---|---|
| review | requestId, title, docPath, changeFiles[], tests, type(design\|lesson), urgency | 单槽检查 → 写 request.json（全部键透传）→ 复制 docPath → docs/<rid>.md |
| approve | requestId, query, sessionId | **cron 过滤不处理**；快道直调读 query/sessionId 裁决，写回 queue.json 任务 + 结果文件 |
