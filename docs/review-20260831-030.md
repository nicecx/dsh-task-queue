# 030 L0 哨兵 H2 swap 阈值放宽（80→90，消除误报）

- requestId: 20260831-030
- 类型: design（监控配置调整，依据 Hermes 侧既有先例）

## 现象

L0 哨兵（qa-agent cron，每 3 小时质测回归）频繁告警 rc=1，唯一失败项 **H2 Swap 使用率**：
- 09-01 00:00 → 83%（阈值 <80%）
- 09-01 03:00 → 73%（过）
- 09-01 06:00 → 84%（阈值 <80%）

## 根因

1. 8GB 内存 + 6GB swap 机型，swap 常态使用率 70-85% 波动（sysctl 实测：6144M 总量、4715M 已用 ≈77%）——macOS 正常交换行为，非内存危机
2. `~/Documents/运维快照/harness/inspection.json` 的 `thresholds.swap_used_percent = 80` 过紧
3. **Hermes 侧先例**（resource_gate.py 行 33-35 注释，2026-08-16 R8 确立）："8GB 机型 swap 70% 常态、85% 阈值曾两次误报；真内存危机指标=H7 换页速率（qa l0 已接管）"——resource_gate 的 swap BUSY 阈值已放宽到 **95**，qa_regression 的 80 未同步

## 方案

`inspection.json`：`swap_used_percent: 80 → 90`

- 对齐 resource_gate 先例（95）但保留 5pt 告警灵敏度（90+ 才告警，真压力可见）
- 其他阈值（disk 85 / memory 20 / load 12）不动
- 真内存危机判定不变：H7 swap 换页速率（qa_regression 行 132-145，swap_page_rate 阈值 50）

## 影响面

- 仅 H2 单项阈值；H1-H6 其余项与 H7 不受影响
- 放宽后哨兵不再每 3 小时误报，真异常（90%+ 或换页激增）仍告警

## 变更文件

- ~/Documents/运维快照/harness/inspection.json（1 个数字）

## 验证

改后手动跑 `env -u PYTHONPATH python3 ~/.hermes/scripts/l0_sentinel.py`（或 `qa_regression.py --tier l0`）→ 期望 rc=0 静默；观察下一轮 3 小时哨兵无告警。
