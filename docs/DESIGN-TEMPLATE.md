# DESIGN-TEMPLATE（设计文档统一模板 v1 · 20260901-006 approved）

> 所有提审设计文档（*.design.md / PROPOSAL.md / 提审 doc）必须符合本节结构。
> 强制关卡：dsh-design-review `checkTemplateSections` 校验必填章节（缺失 → 提审被拒）。

## 必填章节（顺序即模板）

```
# <标题>（设计评审稿 vX）
> 状态 / 类型 / 日期 / 决策点
## 0. 背景与目标
## 1. 复用评估            ← 003 关卡：三源引用或「无复用」逃逸
## 2. 方案（决策 + 理由 + 备选对比）
## 3. 接口与兼容性        ← 对外接口签名/协议版本/兼容策略
## 4. 安全               ← 权限边界/沙箱影响/敏感数据/审批路径（fail-closed 声明）
## 5. 测试方案（T1-Tn）
## 6. 变更文件            ← 路径必须真实存在（与 changeFiles 一致）
## 7. 风险与回滚
```

## 检查清单（提交前自查）

- [ ] 复用评估节：CAPABILITY-INDEX / awesome / GitHub 三源至少一引用，或「无复用」声明
- [ ] 接口与兼容性：新增字段向后兼容 / 破坏性变更声明版本
- [ ] 安全：权限最小化、审批路径、fail-closed
- [ ] 测试方案：用例覆盖边界与回滚
- [ ] 变更文件：每个路径存在，与提审 changeFiles 一致（033 教训）
- [ ] 风险与回滚：失败模式 + 回滚方式
