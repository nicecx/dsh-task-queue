## 024 意见逐条落实（均已实测核实）

### [阻塞] 意见2a：reset tier 调用接口
**实测**: reset_agent.py 无 `--once`；是 request.json 驱动式单次执行器——read_request() 校验 `schema=='dsh-reset-handoff/request'` + `version==1`，缺 id/reason 或 schema 不符 → 打印"无有效请求"退出（实测行 117/473-475）。
**落实**: 消费端 reset handler 流程（先写后调）：
```python
if tier == "reset":
    # 1. 门禁（冷却/多实例）→ defer
    ok, note = guardian_cooldown_ok(); ...
    ok, note = single_instance_ok(); ...
    # 2. 写全字段 request.json（read_request 校验必需）
    write_json(os.path.expanduser("~/.dsh/reset-handoff/request.json"), {
        "schema": "dsh-reset-handoff/request", "version": 1,
        "id": task["payload"]["id"], "reason": task["payload"]["reason"],
        "scope": task["payload"].get("scope", {}), "ts": now_iso(),
        "status": "pending",
    })
    # 3. 调用权威 reset_agent.py（request 驱动，单次执行）
    r = subprocess.run(["python3", RESET_AGENT], capture_output=True, text=True, timeout=300)
    # r.returncode == 0 且 result.json 出该 id → done；否则 failed（计 attempts）
```
**不新增 `--once` 的理由**: 现有语义即"读 request.json → 执行五步 → 写 result.json"的单次执行；消费端强制先落盘全字段 request.json 保证可审计（result.json 带 requestId 回链）。若未来需要免 request 直跑，再单独评估。
**契约表修正**: reset payload 必填键 = `id, reason`（+可选 `scope{restartDshWeb,healthCheck,recoverInterrupted}`）。

### [澄清] 意见3a：单槽 pending 判定字段
**实测**: PROTOCOL 的 result.json 无 status 字段（status 在 request.json）。
**落实**（消费端 review handler，与 lastProcessedId 去重分离）:
```python
def review_slot_ok(rid):
    r = read_json(os.path.join(REVIEW_DIR, "result.json"))
    if r and r.get("requestId") != rid:
        return False, "上一请求未出 result，单槽 defer"
    q = read_json(os.path.join(REVIEW_DIR, "request.json"))
    if q and q.get("status") == "pending" and q.get("requestId") != rid:
        return False, "已有他人 pending，单槽 defer"
    return True, ""
```
去重（lastProcessedId == rid → done）仍在 execute_task 入口，两者职责分离：去重=已完成使命；单槽=避免覆盖他人 pending。
