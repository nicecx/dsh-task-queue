## 021 审核结论与本次修正

### [阻塞] 冷却退避 note 含 elapsed 秒数，defer 输出不稳定
**问题**: `guardian_cooldown_ok()` 的 note `f"reset 10min 退避中（已过 {int(elapsed)}s）"` 含随 tick 单调变化的秒数。defer 分支 log 出 `...退避中（已过 42s）` → 下一 tick `（已过 102s）`，与 020 意见1 要消除的"同一异常因输出变化每 tick 重触发 agent"同源；且 defer 不烧 attempts、不受 MAX_ATTEMPTS=3 约束 → 10min 冷却窗口内每分钟唤醒一次 agent（约 10 次）。
**修复**: note 固定为 `"reset 10min 退避中"`（去掉 elapsed），保证 defer 输出是稳定签名行。
```python
if elapsed < RESET_COOLDOWN_SEC:
    return False, "reset 10min 退避中"
```

### [非阻塞·建议] 诊断细节行拆分 —— 记录 TODO，暂不实施
`single_instance_ok()` note 含 len(pids)/pid 列表、failed 分支含 stderr 前缀，理论上不稳定。审核判定：多实例为瞬时人工干预态、failed 受 MAX_ATTEMPTS=3 约束，均可接受。TODO：如需彻底对齐稳定签名契约，把 pid/stderr 细节移到单独详情行，主签名行仅固定前缀 + 任务 id + 稳定类别词。
