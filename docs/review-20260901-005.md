## 一、设计模板 v1（吸收成熟 ADR 标准）

参考 [joelparkerhenderson/architecture-decision-record](https://raw.githubusercontent.com/joelparkerhenderson/architecture-decision-record/refs/heads/main/README.md#1)（经典 ADR：Status/Context/Decision/Consequences）与 [ai-agent-hub ADR skill](https://github.com/ArieGoldkin/ai-agent-hub/blob/main/skills/architecture-decision-record/SKILL.md?plain=1#L211-L215#1)、[orchestkit ADR skill](https://github.com/yonatangross/orchestkit/blob/main/src/skills/architecture-decision-record/SKILL.md#1)，结合既有互审实践：

```
# <标题>（设计评审稿 vX）
> 状态/类型/日期/决策点
## 0. 背景与目标
## 1. 复用评估（036 关卡：必填，缺节拒绝入队）
   - 本地 CAPABILITY-INDEX / awesome 收录 / GitHub 借鉴
## 2. 方案（决策 + 理由 + 备选对比）
## 3. 接口与兼容性
   - 对外接口签名/协议版本/兼容策略（新增字段向后兼容、弃用路径）
## 4. 安全
   - 权限边界/沙箱影响/敏感数据/审批路径（fail-closed 声明）
## 5. 测试方案（T1-Tn）
## 6. 变更文件
## 7. 风险与回滚
```

## 二、插件开发规范（安全 + 接口兼容）

参考 [Google ADK Agent-Agnostic Safety Plugins](https://github.com/google/adk-samples/blob/8a745552/python/agents/safety-plugins/README.md?plain=1#1)（agent 安全插件模式）与阿里云[可治理插件系统实践](https://developer.aliyun.com/article/1756189#1)（能力清单+策略校验+模型适配），沉淀为 `~/.dsh/PLUGIN-SPEC.md`：

## 三、问题跨 agent 传播机制（核心新增）

**现状缺口**：lesson_review_submit approved 只 append 守则（OPS-GUARDRAILS.md），不检查其他 agent 是否同样存在该缺陷。

**方案：lesson approved → 缺陷传播扫描 → 优先级/严重度 → 修复任务入队**

1. **lesson approved**（现有机制）后新增步骤：
   - 解析 lesson 的**缺陷模式**（如"busy_mutex fs 未导入"→ 模式 `openSync 无 fs 导入`；"kickstart -k 无条件"→ 模式 `launchctl.*-k`）
   - **全机扫描**：grep 所有插件仓库/脚本（~/Documents/Workspace/dsh-*、~/.hermes/scripts、~/.dsh/plugins）匹配缺陷模式
   - 产出**受影响清单**（文件 + 命中行 + 评估）
2. **按优先级/严重度分发**（参考[级联失败策略规范](https://cdn.jsdelivr.net/npm/@liangjie559567/ultrapower@7.8.0/docs/standards/cascade-failure.md#1)思路）：
   - 严重度定级：S1 安全/数据破坏 → 紧急（priority 0）；S2 功能错误 → 高（priority 1）；S3 健壮性/噪声 → 中（priority 2）
   - 每个受影响项生成**修复任务**入队 task-queue（tier=review 或新 tier=fix，payload 含模式/文件/严重度）
   - 逐项修复 → 回归测试 → 完成（修复闭环与 lesson 同链）
3. **一致性保障**：修复后把模式加入该插件的"已知缺陷清单"（防复发）；同模式新代码在评审关卡（036）校验

**执行方**：lesson 传播扫描由 dsh-design-review 插件（lesson approved 钩子）或 Hermes 侧消费端扩展实现——实现细节 P1 再定，本方案定机制与分级。

## 四、实现一致性保障

- **模板关卡**（036 已立）+ 本模板（037）合并为单一校验（dsh-design-review 入队校验：章节齐全）
