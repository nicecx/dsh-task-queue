## 方案（契约新增节内容）

### 架构总览（写入 DSH-HERMES-CONTRACT.md，置于资产清单后）

```
┌─ 应用层 ────────────────────────────┐
│  dsh-auto-approver（审批代理）       │ ← 运行时权限拦截，Hermes 裁决
│  dsh-design-review（设计评审）       │ ← 开发期文档评审，入队提审
│  dsh-reset-handoff（重启托管）       │ ← 重启请求托管执行
└──────────────┬──────────────────────┘
               │ 全部入队
┌──────────────▼──────────────────────┐
│  dsh-task-queue（队列中枢·唯一真相源） │ ← queue.json + busy 锁 + 消费端 cron
└──────────────┬──────────────────────┘
               ▼
        Hermes 守护（审核裁决 / reset 执行 / 审批语义裁决）
```

### 联动点（数据流，均已实测）

1. **审批×队列**：approval 请求 → 入队 approve tier（审计轨迹）→ 快道同步直调 Hermes 裁决（busy 锁与消费端互斥）→ 结果写 results/ + 任务 done
2. **评审×队列**：设计文档/lesson → auto-submit 入队 review tier → 消费端出队 → 单槽检查 → 写 request.json → Hermes 审核 → 结论按 sessionId 路由回发起会话
3. **重启×队列**：reset 请求入队（priority 0 最高）→ 消费端门禁（10min 退避/多实例）→ 写 reset-handoff/request.json → 调 reset_agent.py（预检/重启/健康检查/恢复）
4. **共享机制**：busy 锁（.hermes-busy）串行化所有写队列操作；requestId 单一编号源（docs/ 扫描）；fail-closed（Hermes 不可用→转人工）
5. **独立性**：各插件可单独使用（审批可无队列直调兜底；评审可独立提审）；组合时协议自动织合

### 独立性说明（用户确认 2026-09-02）

- 不合并为单体插件：职责分层（运行时拦截/开发期评审/基础设施），避免依赖倒置与循环依赖
