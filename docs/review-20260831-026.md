## 025 意见逐条落实

### [阻塞] review_slot_ok 单槽判定比较对象错误 → review tier 恒 defer 死锁
**问题**: 025 版 `if r and r.get("requestId") != rid` 拿 result.json.requestId（恒为上一次已审 id，如 024）与新 rid（025）比较 → 对新任务恒为真 → 永远 defer，新 review 永远写不进 request.json。
**修正**（对照 PROTOCOL drain 校验：比较对象 = 当前 pending 的 request.json.requestId）:
```python
def review_slot_ok(rid):
    """单槽：若存在他人 pending 且该 pending 尚未出 result → defer。"""
    q = read_json(os.path.join(REVIEW_DIR, "request.json"))
    if q and q.get("status") == "pending" and q.get("requestId") != rid:
        r = read_json(os.path.join(REVIEW_DIR, "result.json")) or {}
        if r.get("requestId") != q.get("requestId"):
            return False, "上一请求未出 result，单槽 defer"
    return True, ""
```
语义：只有"他人 pending 且其 result 未出"才 defer；本任务 rid 与 pending 相同（重复提交）或他人 pending 已出 result → 放行。等价判定：`state.json.lastProcessedId != q.requestId` 判占用（drain 校验同款），实现取上述 result.json 形式（字段实测：result.json 无 status，request.json 有 status）。

**T8 测试按修正后语义写**（勿按 buggy 版固化）：
- T8a: request.json 有他人 pending（rid≠当前，status=pending）+ result.json.requestId 为更早 id → defer
- T8b: request.json 有他人 pending + result.json.requestId == 该 pending rid（已出结果）→ 放行
- T8c: 无 pending（request.json 缺/非 pending）→ 放行
